# Guide: Reaching an EC2 instance three ways

**Related:** [ADR-0022](../../adr/0022-the-local-aws-environment.md), [`infra/modules/ec2-instance`](../../infra/modules/ec2-instance/main.tf),
[journal](../journal/2026-09-24-reset-and-local-aws-rebuild.md), [upstream findings](../research/2026-09-24-floci-upstream-findings.md)
**Evidence:** verified on Floci (all three paths tested on 2026-09-24). Not verified on real AWS, where the details differ as noted.

## The idea

An EC2 instance is a server you cannot walk up to. There are three standard ways in, and knowing which to use, and
what each one exposes, is a core cloud skill:

| Way in | How it works | What it exposes |
|---|---|---|
| **SSH** | You hold a private key; the instance holds the matching public key. You connect to port 22. | An open port. Whoever can reach it can try to log in. |
| **SSM Session Manager / Run Command** | The instance's SSM agent calls *out* to AWS Systems Manager; you talk to SSM through the AWS API. | No open port and no key. Access is controlled by IAM, and every command can be logged. |
| **Console terminal** | A browser shell (in AWS: EC2 Instance Connect or Session Manager, started from the console). | Nothing extra: it rides on one of the two above. |

AWS's own advice is to prefer SSM: closing port 22 removes the biggest thing an attacker could aim at, and IAM gives
you audit trails that SSH keys do not. SSH remains common for tools that need it (file copy, port forwarding).

## How it works here

`scripts/dev-up.ps1` builds one instance, the **workstation** (Amazon Linux 2023), from
[`modules/ec2-instance`](../../infra/modules/ec2-instance/main.tf), and prints the commands to reach it.

**1. The console terminal.** Open http://localhost:9877, go to EC2, open the instance, and use the Terminal tab.
floci-dash runs `docker exec -it <container> /bin/bash` inside the instance's container over the Docker socket. On
real AWS the equivalent is the console's "Connect" button.

**2. SSH from your own terminal.**

```powershell
ssh -i "$HOME\.ssh\floci-dev" -p <port> -o StrictHostKeyChecking=no -o UserKnownHostsFile=NUL root@127.0.0.1
```

`dev-up` prints the exact line, with the port. What happens behind it:
1. `dev-up` creates a dedicated key `~/.ssh/floci-dev` once, and OpenTofu imports only the **public** half as an EC2
   key pair. The private half never leaves your machine.
2. The instance is launched with that key pair's name. Floci copies the public key into `/root/.ssh/authorized_keys`
   inside the container at boot.
3. Floci's images are minimal containers with no SSH server (real AMIs ship one), so the instance's **user data**, a
   script that runs once at first boot, installs and starts `sshd`. This is what user data is for.
4. Floci maps the container's port 22 to a host port between 2200 and 2299.

**3. SSM Run Command.**

```powershell
aws --profile floci ssm send-command --instance-ids <id> --document-name AWS-RunShellScript --parameters commands="cat /etc/os-release"
aws --profile floci ssm get-command-invocation --command-id <CommandId> --instance-id <id>
```

`send-command` returns a command ID straight away; you poll `get-command-invocation` for `Status`
(`InProgress`, `Success`, `Failed`) and the output. The instance profile in the module attaches
`AmazonSSMManagedInstanceCore`, the policy real AWS needs for the SSM agent to register the instance.

**Not supported by Floci 2.1.0: Session Manager's interactive shell.** `aws ssm start-session` returns
`UnsupportedOperation`. Run Command is the working SSM path here; the console terminal covers the interactive need.

## Why this way

- **Key pair imported, not generated by AWS.** `CreateKeyPair` on Floci returns dummy key material, and generating
  a key in OpenTofu would put the private key in the state file. Importing a public key you made yourself is also
  what security teams prefer on real AWS.
- **A module, not a one-off.** The security group, instance role, instance profile and instance are the same set of
  parts a real workload needs, so they are reusable and reviewable.
- **IMDSv2 required** in the module: the instance metadata service then answers only requests with a session token,
  which blocks server-side request forgery from stealing the instance's credentials.

## Watch out for

- **Floci publishes the SSH port on every network interface, not just this machine.** `netstat -ano | findstr :2201`
  shows `0.0.0.0:2201`. Login needs your key, so this is not an open door, but it is a listening port on your LAN, and
  the same is true of any port a security group opens (Floci publishes those on 30000 to 30999). Floci has no setting
  for the bind address. To block network access and keep local access, run this once in an **elevated** PowerShell
  (untested by the project: it needs administrator rights, so it is your decision to apply; Windows Firewall does
  not filter loopback traffic):

  ```powershell
  New-NetFirewallRule -DisplayName "Floci EC2 ports: block from network" -Direction Inbound -Protocol TCP -LocalPort 2200-2299,30000-30999 -Action Block -Profile Any
  # to undo:
  Remove-NetFirewallRule -DisplayName "Floci EC2 ports: block from network"
  ```

  Verify from another device on your network that `Test-NetConnection <your-ip> -Port 2201` fails, and from this
  machine that the `ssh` command still works.
- **The security group's source range is not enforced.** The module allows SSH from `127.0.0.1/32`; Floci publishes
  the port regardless. On real AWS the group is the firewall, and this range would be enforced. Never leave `0.0.0.0/0`
  on port 22 on a real account.
- **IMDSv2 "required" is not enforced by Floci either**: a token-less request to the metadata service returns 200.
  Real AWS returns 401.
- **`StrictHostKeyChecking=no` and `UserKnownHostsFile=NUL` are for this throwaway target only.** A new instance has
  a new host key, so SSH would warn every time. Turning host-key checking off for a real server would let someone
  impersonate it.
- **The key has no passphrase.** It opens a container on this machine and nothing else. Do not reuse it anywhere.
- **User data runs once, at first boot.** Editing it does not change a running instance; the module sets
  `user_data_replace_on_change`, so OpenTofu replaces the instance instead of silently ignoring the edit.
- **The web terminal needs the Docker socket and only works on images with bash** (Alpine does not have it). floci-dash
  does not check which website opens its terminal WebSocket (tested), so close the tab when you are not using it.
- **Login is `root` here** because Floci's instances are containers. Real Amazon Linux uses `ec2-user`, and Ubuntu uses
  `ubuntu`; root login is normally disabled.
- **An instance profile is not a user.** It is the role the instance itself uses, for example to call SSM or read S3,
  and it is what makes SSM work; forgetting it is the most common reason "SSM does not see my instance" on real AWS.

## Check yourself

<details><summary>Why does AWS recommend SSM over SSH?</summary>

SSM needs no inbound port, so there is nothing to scan or brute-force, and no keys to distribute or rotate. Access is
an IAM permission, and sessions and commands can be logged to CloudWatch or S3. SSH is still used when a tool needs it.

</details>

<details><summary>What is a bastion host, and why do people still build them?</summary>

A hardened instance in a public subnet that is the only way into private subnets over SSH. Session Manager replaces it
in most designs, but a bastion remains where SSH is required, for example for tunnelling to a database.

</details>

<details><summary>SSM says the instance is not managed. What do you check?</summary>

That the instance has an instance profile with `AmazonSSMManagedInstanceCore`, that the SSM agent is installed and
running, and that the instance can reach the SSM endpoints (through a NAT gateway or VPC endpoints) on port 443.

</details>

<details><summary>The security group allows SSH from 10.0.0.0/16. Who can connect?</summary>

Only sources inside that range, when they hold the key. A security group is a stateful allow-list: everything not
listed is denied, and return traffic is allowed automatically.

</details>
